## 3. AgntID — what the docs settle (docs/agntid-context.md)
- Runtime 2.0.0 is customer-hosted Docker (`achr-runtime`, `achr-intent-parser`; ~4 GB RAM, ~900 MB
  model on first start). Portal app.agntid.ai = control plane. Local UI :8080, MCP :8082/mcp.
- MCP servers are added in the portal; runtime prefixes tool names (`afrs.get_financials`, exposed
  over MCP as `afrs_get_financials`). One runtime fronts many servers.
- Servers must be reachable **from inside the container**: bind `0.0.0.0` (not 127.0.0.1), portal URL
  `http://host.docker.internal:<port>/mcp`.
- Protection profile (Low/Medium/High) caps visible tools; Medium hides delete/execute/high-impact.
  A send-email tool may be hidden → check classification, correct label or use Low + policies.
- Policies: portal input constraints (docs show numeric min/max) + custom Rego (not documented here).
- Decisions: allow, deny, review-required (`ReviewStatus`, `ApprovalEvidence` bound to args digest),
  tool output withheld (LLM-based intent only). **No native narrow.** Docs: don't silently change args.
- Intent engine: Standard (default) vs LLM-based (needs OpenAI credential in portal) — task analysis,
  shortlist, tool-output protection, final-answer validation. Check engine used in Call Flow.
- SDK 0.2.0 from source (`git clone` + `pip install -e .`); wheel is 0.1.1. Pattern: one task per user
  request, reuse task_id; child agents via `DelegationContext` / `send_delegation_open`;
  `send_task_open_details` + `filter_tools_for_task` for prompt-aware shortlist; `DenialResult`.
- `user_id` must be stable opaque ID (not email) → use Google `sub` or a hash.
- OAuth client access disables Simulator.

### Changes this implies for our code
1. Gateway: map our tool names → prefixed runtime names (agent code unchanged).
2. Gateway: one root task per report run + one delegation per agent (Research, News, Writer,
   Distributor) instead of one task per agent step.
3. NARROW stays in our layer, logged as ours: `send_report` takes **one recipient per call** (mixed list
   = some allowed, some denied); over-limit news params denied by AgntID, app re-requests within limits.
4. ESCALATE → review-required + our Streamlit approval as evidence (flow to confirm).
5. Servers bind `0.0.0.0` when used with AgntID.
6. Local engine mirrors AgntID rules so `guarded` stays an offline stand-in.
